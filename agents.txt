# AGENTS.md

## Project

This is an MVP for a careers/education route planner for 16–19-year-olds.

## Product principles

- The product must be supportive, not judgemental.
- Never describe students as smart/dumb.
- Use terms like high academic attainment, grade-constrained, debt-averse, location-constrained, practical learner, competitive-course applicant.
- Recommendations must be explainable.
- Do not present career advice as guaranteed.
- Every recommendation should show reasons, risks, missing information, and next steps.
- Avoid dark patterns in freemium logic.

## Engineering principles

- Use TypeScript.
- Keep scoring logic pure and testable.
- Separate UI from recommendation logic.
- Put recommendation/scoring code in `lib/scoring`.
- Put mock route data in `data/routes`.
- Put roadmap templates in `data/roadmaps`.
- Add unit tests for scoring logic.
- Add test personas in `data/test-personas`.

## MVP constraints

- Do not integrate live UCAS, GOV.UK, or apprenticeship APIs yet.
- Use mock data for initial validation.
- Do not add payments until the core experience works.
- Do not add complex AI generation until deterministic scoring is reliable.
- Do not collect unnecessary sensitive data.

## Commands

Use the project’s actual commands once created.

Expected commands:
- npm run dev
- npm run lint
- npm run test
- npm run build

## Definition of done

A task is complete only when:
- the feature works on mobile
- there are no obvious TypeScript errors
- relevant tests pass
- the UI gives supportive, explainable guidance
- the implementation does not break existing flows
